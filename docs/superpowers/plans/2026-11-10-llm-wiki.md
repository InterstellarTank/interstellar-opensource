# LLM Wiki Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use the `subagent-driven-development` (recommended) or `executing-plans` skill to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a persistent, LLM-maintained wiki (`raw/` sources + `wiki/` knowledge base + a `## LLM Wiki` schema in `AGENTS.md`) to the World of Tanks 0.6.5 server repository.

**Architecture:** Two root folders — immutable `raw/` sources and agent-owned `wiki/` with `index.md`, `log.md`, `overview.md`, and four category folders. A `## LLM Wiki` section in `AGENTS.md` defines ownership, page conventions, and the ingest / query / lint workflows, with explicit boundaries against `.scratch/`, `GLOSSARY.md`, and ADRs.

**Tech Stack:** Markdown, Obsidian wikilinks; no code.

**Spec:** `docs/superpowers/specs/2026-11-10-llm-wiki-design.md`

## Global Constraints

- `raw/` is read-only for the agent: never edit, move, or delete files there.
- `wiki/` is agent-owned; the human reads it.
- Wiki prose is Ukrainian; technical terms stay in English.
- Every page is listed in `wiki/index.md`; every ingest, query, and lint pass appends to `wiki/log.md`.
- Factual claims cite repo-relative `raw/<path>` paths.
- `GLOSSARY.md` / `docs/adr/` own decisions and vocabulary; the wiki links to them, never duplicates them.
- `.scratch/` owns tasks; the wiki holds knowledge only.
- Obsidian vault root is `wiki/`; category folders are `sources/`, `concepts/`, `entities/`, `analyses/`.
- No git repository exists: commit steps are skipped until `git init`.

## Review Focus

- The agent edits `raw/` → Ingest requires a final "no file under `raw/` was modified" check.
- An ingest writes a page but skips `index.md`/`log.md` → both are mandatory ingest steps.
- A wiki page duplicates `GLOSSARY.md`/ADR content → Page conventions say link, and Lint flags duplicates.
- A page states a fact without a citation → Page conventions require a `raw/...` citation per claim.
- Wiki prose drifts to English → the language rule is written in the schema and checked in Task 2.

### Task 2: Add the `## LLM Wiki` schema to `AGENTS.md`

**Files:**

**Interfaces:**
- Consumes: folder names and file conventions from Task 1.
- Produces: schema headings read by every future session: `## LLM Wiki`, `### Files`, `### Page conventions`, `### Ingest`, `### Query`, `### Lint`, `### Boundaries`.

- [ ] **Step 1: Verify the section is absent**

Run: `Select-String -Path AGENTS.md -Pattern '^## LLM Wiki'`
Expected: no match.

- [ ] **Step 2: Insert `## LLM Wiki`**

Content (English, matching the file's existing style):
- **Files**: `raw/` immutable sources; `wiki/` agent-owned; `index.md` catalog; `log.md` append-only record; `overview.md` evolving synthesis; `sources/`, `concepts/`, `entities/`, `analyses/` categories.
- **Page conventions**: one topic per page; `#` title; `[[wikilinks]]`; each factual claim cites `raw/<path>`; contradictions flagged in a blockquote; Ukrainian prose, English technical terms; every page listed in `index.md`.
- **Ingest** (the human drops a source in `raw/` and asks to ingest it): read the source fully → share 3–5 key takeaways and open questions with the human → write `wiki/sources/<slug>.md` → create or update related `concepts/` and `entities/` pages → update `index.md` → flag contradictions → append `## [YYYY-MM-DD] ingest | <title>` to `log.md` → confirm no file under `raw/` was modified.
- **Query**: read `index.md` first → read the relevant pages → answer with citations to wiki pages and raw sources → offer to file valuable answers as a new page (then update index and log) → append `## [YYYY-MM-DD] query | <question>` to `log.md`.
- **Lint**: check contradictions, stale claims, orphan pages, missing pages for mentioned concepts, missing cross-references, and data gaps; report findings, fix index/link issues, propose content fixes for approval; append `## [YYYY-MM-DD] lint | <scope>` to `log.md`.
- **Boundaries**: `GLOSSARY.md` and `docs/adr/` own decisions and vocabulary — link, don't duplicate; `.scratch/` owns tasks; `research` output is a candidate source to ingest after review; these are workflows in this file, not skills — do not route them through the `### Skill execution` table.
